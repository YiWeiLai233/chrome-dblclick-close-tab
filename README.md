# 双击关标签

在网页内容区**双击**，直接关掉当前标签页。Chrome / Edge 通用（Manifest V3）。

> 先说清楚一件事：Chrome 扩展**拿不到标签栏（tab strip）上的鼠标事件**。Firefox 有原生的
> `browser.tabs.closeTabByDblclick`，Chrome 一直没有对应的 API，也没有权限去监听浏览器 UI。
> 所以这个扩展做的是「**双击页面主体区域**关闭标签」+「**快捷键**关闭标签」这两条通道，
> 这已经是 Chrome 上纯扩展能做到的最接近的形态。

## 安装

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录
4. 装完回到网页直接双击就能用。安装/更新扩展时后台会自动把内容脚本补注入到已经打开的
   标签，一般不需要自己刷新——但在扩展装好之前就打开的页面偶尔会注入失败，双击没反应就
   先刷新一次

不想 clone 仓库的话，直接去 [Releases](https://github.com/YiWeiLai233/chrome-dblclick-close-tab/releases)
下 `chrome-dblclick-close-tab-*.zip`，解压后按上面第 1–3 步加载解压出来的目录即可。

## 快捷键

标签栏双击做不到，但键盘可以：装好之后按 **`Alt+Shift+W`** 直接关掉当前标签页。

- 这条快捷键由浏览器自己派发，页面脚本拦不住，在网页、弹窗、开发者工具里都生效
- 想换键位：地址栏手动输入 `chrome://extensions/shortcuts`（扩展没有权限用 API 打开这个页面），
  找到「双击关标签」改掉即可。设置页会显示当前实际生效的键位
- 如果显示「未设置」，通常是默认键位被别的扩展占了，去上面那个页面重设

## 双击间隔

设置页有个「**双击间隔上限**」滑块（120–1000 ms，默认 400 ms）：两次点击的间隔小于它才算一次
双击。手慢容易点不出来，就把值调大；怕误触就调小。

为什么这个值能自定义、而浏览器自己的双击判定不能：扩展没有用浏览器原生的 `dblclick` 事件，
而是自己配对两次 `mousedown`，所以间隔完全由扩展决定。原生 `dblclick` 的阈值来自操作系统的
「双击速度」设置，页面和扩展都改不了。

## 双击了没反应？

打开设置页，把「**显示未触发原因**」打开，再双击一次，页面底部会直接告诉你原因：

| 提示 | 意思 |
| --- | --- |
| 命中了可交互元素 | 双击落在链接/按钮上，那是页面自己的语义 |
| 命中了编辑器 | contenteditable、Monaco、CodeMirror 等，双击是选词 |
| 命中了 `<input>` 控件 | 输入框、下拉框、视频、canvas |
| 双击前已有选中文字 | 先点一下空白处取消选区再双击 |
| 当前站点已豁免 | 去设置页把这个域名从豁免列表删掉 |
| 扩展已停用 | 总开关没开 |
| 已保留最后一个标签页 | 窗口只剩一个标签，`keepLastTab` 在保护它 |

## 行为

默认是「智能」模式，只在确定用户不是在干别的事情时才关：

| 你双击的地方 | 结果 |
| --- | --- |
| 普通正文、空白处 | **关闭标签** |
| 输入框、下拉框 | 不关（双击是选词） |
| 链接、按钮、tab、复选框等可交互元素 | 不关（双击有页面自己的语义） |
| 富文本 / 代码编辑器（contenteditable、Monaco、CodeMirror…） | 不关 |
| 双击前已经选中了文字 | 不关 |
| 视频、音频、canvas、iframe | 不关 |
| 按住 Ctrl / Shift / Alt / Cmd 双击 | 不关（视为刻意操作） |
| 窗口里只剩最后一个标签 | 不关，底部弹一条提示 |

想更激进可以在设置页切到「任何位置」模式：只要不在输入控件里，双击哪儿都关。

## 设置

点工具栏图标或扩展详情页的「扩展程序选项」：

- **启用双击关闭**：总开关
- **双击间隔上限**：120–1000 ms，两次点击的间隔小于它才算双击
- **保留最后一个标签**：默认开，避免把窗口一起关掉
- **触发范围**：智能 / 任何位置
- **站点豁免**：一行一个域名，写主域名即覆盖子域（`example.com` 也管 `docs.example.com`）
- **显示未触发原因**：排查用，双击没关时在页面底部说明原因

设置存在 `chrome.storage.sync`，改动立刻生效，不用刷新页面。

## 实现要点

- `content.js` 只在**捕获阶段**监听 `mousedown`，页面自己的处理器藏不掉这个事件
- **不使用原生 `dblclick`**：原生双击的等待上限由操作系统的「双击速度」决定，页面脚本
  既读不到也改不了，要做「自定义间隔」就只能自己配对两次 `mousedown`，顺便还能校验两次
  点击的位置（`SAME_SPOT = 12px` 内才算同一次双击）
- 判断逻辑放在内容脚本里，因为只有它能看见 DOM（焦点在哪个输入框、有没有选中文字）
- 真正的关闭动作在 `background.js`，内容脚本不碰 `chrome.tabs`
- 安装/更新时 `background.js` 会把 `content.js` 补注入到所有已打开的 http/https 标签，
  否则扩展装好前就开着的页面双击没反应，用户会以为坏了
- 「有选中文字就不关」这一条有个坑：**双击本身就会选中一个词**，浏览器在第二次
  `mousedown` 时已经把选区做好了，所以必须在第一次 `mousedown` 时取一次快照，
  拿的是「双击开始前」的状态

## 端到端测试

```powershell
node tools/e2e.mjs
```

真的启动一个 Chrome、真的装扩展、用 CDP 派发真实鼠标事件，然后检查标签到底关没关。12 条用例覆盖上面
行为表里的每一项，包括「间隔小于上限就关、超过上限就不关」这一对。

注意两点，都是踩过的坑：

1. **Chrome 137+ 的正式版直接忽略 `--load-extension`**。stderr 里会明确写
   `--load-extension is not allowed in Google Chrome, ignoring.`，扩展压根不会加载，
   测试会静默地全绿/全红。所以 `tools/e2e.mjs` 改用浏览器级 CDP 命令
   `Extensions.loadUnpacked` 来装载扩展。
2. 测「保留最后一个标签」时必须真的把窗口收到只剩一个——只断开 WebSocket 不会关标签，
   前一个用例的页面还开着，测出来的就不是单标签场景。

图标用 `tools/make_icons.py` 生成（Pillow，超采样后缩放），产物在 `icons/`。

## 目录

```
manifest.json      扩展清单（MV3）
background.js      service worker：判断「最后一个标签」并关闭
content.js         内容脚本：配对两次点击、判断该不该关，然后通知后台
options.html/js    设置页
popup.html/js      工具栏弹窗：总开关 + 本页豁免
ui.css             设置页与弹窗共用的样式
icons/             图标（tools/make_icons.py 生成）
tools/             图标生成脚本与 e2e 测试
```
